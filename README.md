# Бот группы L2Hub в Telegram

Сам пишет в группу `l2hub`, по темам:

| Тема | Что пишет | Откуда берёт |
|---|---|---|
| 🚀 Обновления (`TG_TOPIC_UPDATES`) | «Вышла L2Hub v0.5.180» и 3–7 пунктов, что нового | теги и `CHANGELOG.md` публичного `kraffty4/L2Hub`; пересказ — DeepSeek |
| 🔧 Система (`TG_TOPIC_SYSTEM`) | понятное игрокам объяснение изменений, текущая готовность и ссылки на технические подробности | закрытый `kraffty4/L2Hub-bridge`, клон по deploy key; краткий пересказ — DeepSeek |
| 📦 Наработки (`TG_TOPIC_WORK`) | архив и текст к нему | папка `outbox/` на компьютере: пара `тема.zip` + `тема.md` |
| 📌 Планы (`TG_TOPIC_PLANS`, необязательно) | общий обзор: исполнители, хроники, готовность, замечания и возможные пересечения | тот же опубликованный снимок `tasks/`, без отдельного ручного списка |

На сообщения в группе бот не отвечает и ничего не читает: только постит. С другими ботами группы не пересекается.

## Где работает

- **Релизы и мост** — GitHub Actions, раз в полчаса (`.github/workflows/bot.yml`, можно запустить вручную: Actions → bot → Run workflow). Мост клонируется по deploy key только на чтение, который Кирилл добавил к `L2Hub-bridge`. Что уже отправлено, бот помнит в `state/seen.json` и коммитит его обратно — повторов нет. Упавший прогон красный, GitHub пришлёт письмо.
- **Наработки** — с компьютера: `outbox.cmd` (или `python l2hub_tg.py outbox`), архивы ведь появляются здесь.

Секреты репозитория (Settings → Secrets and variables → Actions): `TELEGRAM_BOT_TOKEN`, `LLM_API_KEY` (DeepSeek), `TG_CHAT_ID`, `TG_TOPIC_UPDATES`, `TG_TOPIC_SYSTEM`, `BRIDGE_DEPLOY_KEY` (закрытая часть ключа). В коде ключей нет.

## Локально

Файл `.env` рядом со скриптом (образец — `.env.example`, в git не попадает) с теми же ключами плюс `TG_TOPIC_WORK`.

- `python l2hub_tg.py topics` — id тем: сначала напиши в каждую тему `/id@<бот>` (бот с приватностью видит только команды).
- `python l2hub_tg.py init` — запомнить текущую версию и мост, не вываливая историю (первый запуск).
- `python l2hub_tg.py watch --dry-run` — что бот отправил бы, без отправки.
- `python l2hub_tg.py plans` — прочитать общий план без публикации в Telegram.
- `python l2hub_tg.py plans --find "краски" --chronicle "High Five" --json` — найти существующие работы для агента. Источники других хроник сохраняются и отмечаются отдельно.

Длинные сообщения делятся по целым строкам; при длинной строке сохраняются ссылки, HTML-сущности и вложенная разметка. Лимит считается по отображаемому тексту. Сводка отмечается отправленной после успешной отправки всех частей.

Сообщения и файлы в группу отправляются с паузой 3,2 секунды. При ответе Telegram 429 бот выдерживает `retry_after` с запасом и повторяет только отклонённый запрос (не более трёх повторов). Новости моста отмечаются по мере доставки: после частичного сбоя уже принятые новости не отправляются заново. Остальные ошибки остаются видимыми в Actions.

### Как читается «Система»

Новость объясняет, что изменили и что это даёт игроку; ограничения и нужную хронику сохраняет из сообщения автора. Имена классов, коммиты и патчи доступны по ссылке «Подробности и проверка». Изменения задач показываются названиями, именами участников и обычными словами вместо внутренних ID.

В ежедневной сводке отдельно показаны вышедшие изменения, принятые для будущей версии, текущая работа и готовое у авторов без подтверждённого общего выпуска. Эти статусы определяются полями моста и опубликованными тегами, а не нейросетью. Организационные реестры сведены в счётчик; длинные списки показывают первые восемь тем и ссылку на весь список.

Один запрос к DeepSeek обрабатывает пачку новостей/названий. Если пересказ недоступен или ответ некорректен, бот продолжает работу с исходным названием и ссылкой. Кэш объяснений живёт только в памяти запуска: тексты закрытого моста не попадают в публичный `state/seen.json`. Отметки доставки зависят от исходных записей, поэтому иной пересказ при повторном запуске не создаёт дублей.

### Общие планы и поиск перед началом работы

Администратор создаёт тему «Планы» и задаёт её ID в секрете Actions `TG_TOPIC_PLANS`. При отсутствии значения поведение бота не меняется. Первый запуск публикует разделы и навигационный обзор без уведомлений; затем информатор редактирует эти же сообщения только при изменении данных. Администратор может закрепить обзор вручную; права управления темами и чужими сообщениями боту не нужны.

В обзоре отдельно показаны активная работа, планы, готовое у авторов, принятые будущие версии, опубликованное и организационные карточки. Исполнители и хроники взяты из карточек, «план» не считается начатой работой. «В работе» с текстом «Не начато» и явно оставленные старые статусы помечаются для сверки.

Сходство названий/ссылок даёт только подсказку. Другие хроники показываются как возможность переноса; явно заданные `source`/`duplicate_of` сохраняются как связи. Бот ничего не назначает, не закрывает, не объединяет и не изменяет в мосте. Дополнительные поля и общий порядок согласуются в [предложении](https://github.com/kraffty4/L2Hub-bridge/blob/main/proposals/shared-plans.md).

Команда `plans` сначала делает `git fetch origin`, затем читает `origin/main` через `git archive`: незакоммиченные записи и локальные черновики других агентов не публикуются. JSON содержит SHA снимка и дерева задач, карточки, источники, причины замечаний и связанные работы. Перед изменением кода агент проверяет исходную карточку, реальную реализацию и закрепляет исполнителя по правилам моста.

Полный вывод и заметки закрытого моста нельзя сохранять в публичные файлы/логи этого репозитория. В `state/seen.json` хранятся только ID страниц, контрольные суммы и отметка снимка; тексты обзора остаются в группе и частном мосте.

Проверка без Telegram и нейросети: `python -m unittest -v`. Она также выполняется в GitHub Actions перед запуском бота.

## Как Claude выкладывает наработки

Закончил тему — кладёт в `outbox/` архив и текст с одним именем (`hunter-rift.zip` + `hunter-rift.md`) и запускает `outbox.cmd`. Первый абзац `.md` становится подписью к файлу; после отправки оба переезжают в `outbox/sent/`.

## Требования

Python 3.12+ и `requests` (`pip install -r requirements.txt`); локально мост ищется в `D:\Games\L2Hub-bridge` (переменная `BRIDGE_DIR`).
